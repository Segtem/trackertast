tracker local en markdown

Tareas que viajan en tu repositorio.

Un tracker de tareas en archivos Markdown dentro de tu proyecto, pensado para que personas y agentes de programación se pasen el trabajo sin perder contexto, sin bases de datos y sin servicios externos. Cada tarea vive en su propia carpeta bajo tareas/ y Git guarda la historia cuando hacés commit.

El ciclo de vida de una tarea local

ESCENA PIXEL ART NATIVA
El ciclo de vida de una tarea en Oracle Task consta de cinco etapas: 1. Crear tarea: se genera la subcarpeta tareas// y TAREA.md con estado ABIERTA. 2. Registrar evidencia: notas de avance en UTC y copia de archivos locales como calibracion.csv. 3. Relevo colaborativo: redacción del único ## Próximo paso al final para pasar el testigo a otra persona o agente. 4. Cierre y Git: tasks close marca CERRADA atómicamente; la persona confirma en Git (git commit) para registrar historia de versiones. 5. Reabrir: tasks reopen restaura ABIERTA conservando íntegras todas las notas históricas. Consultá los detalles debajo.

Avanzá a tu ritmo o reproducí el recorrido animado.

01 / 05
PERSONA O AGENTE + CLI

1. Nace una tarea en su propia carpeta

Una persona o un agente inicia el hilo de trabajo. Oracle Task crea la subcarpeta tareas/20261004-012404-sensor/ con su plantilla TAREA.md, metadatos estructurados (ESTADO: ABIERTA, PRIORIDAD: 70, ETIQUETAS: sensor) y formato Markdown estándar.

Comando a ejecutar
tasks new "Investigar defecto en sensor" --etiqueta sensor --prioridad 70 --sufijo sensor
ENTRA
Una necesidad, defecto observado o acuerdo de trabajo.
SALE
Carpeta tareas/<ID>/ con plantilla TAREA.md y estado ABIERTA.

Límites y responsabilidades

¿Quién hace qué?

La persona o el agente ejecuta el comando. El CLI crea los archivos locales en tu disco.

Límite explícito

El tracker no requiere servidores remotos ni bases de datos. Todo vive dentro de tareas/ en tu repositorio.

Simulación demostrativa: ID ilustrativo, no una tarea creada por la página. La CLI genera un ID con fecha UTC y sufijo explícito. En tu máquina, usá tasks new "..." --sufijo <nombre> para crear tareas reales con sufijos memorables.

roles y fronteras

Cada parte con su responsabilidad

Oracle Task no inventa aprobaciones automáticas, no ejecuta tests ni crea commits por sorpresa. Las responsabilidades se reparten así.

Persona La dirección y el juicio

Decide qué construir y cuándo cerrar. Es la responsable de:

  • Aceptar el alcance y prioridad de la tarea.
  • Ejecutar suites de pruebas y validar el software.
  • Hacer git add y git commit para guardar la historia.
Agente La asistencia técnica

Colabora en la resolución de problemas en sesiones autónomas o asistidas:

  • Carga el contexto completo con tasks show.
  • Registra notas de avances con tasks note.
  • Redacta el único ## Próximo paso antes de terminar su turno.
Tracker (tasks) El hilo de trabajo

Administra las carpetas y archivos TAREA.md de forma atómica:

  • Crea tareas, registra notas y copia adjuntos locales.
  • Cambia atómicamente el estado a ABIERTA o CERRADA.
  • Audita la validez de los archivos con tasks review.
Git El historial de versiones

Conserva los cambios del repositorio y las tareas en el tiempo:

  • Guarda historia SOLO si la persona hace git commit.
  • Los commits nombran la tarea (<ID>: ...).
  • tasks follow audita la cobertura de archivos frente a HEAD.

en marcha

Recorrido básico en seis pasos

Seis comandos esenciales para inicializar, crear, documentar, listar, inspeccionar y cerrar tareas, Las salidas muestran IDs y fechas ilustrativos. La CLI genera tus IDs reales; estos comandos usan el sufijo sensor.

1

Inicializar el repositorio

Desde la carpeta de tu proyecto, crea el directorio tareas/ con su archivo explicativo README.md.

tasks init 
$ tasks init
Tracker de tareas inicializado en ./tareas
2

Crear una tarea

Crea una nueva carpeta con su plantilla TAREA.md, metadatos y sufijo determinista.

tasks new 
$ tasks new "Investigar defecto en sensor" --etiqueta sensor --prioridad 70 --sufijo sensor
Tarea creada: 20261004-012404-sensor
Ruta: ./tareas/20261004-012404-sensor/TAREA.md
3

Asentar una nota de avance

Agrega notas de progreso fechadas en UTC de forma atómica en el cuerpo de la tarea.

tasks note 
$ tasks note sensor "Medición preliminar en banco de pruebas"
Nota agregada a la tarea 20261004-012404-sensor
Documento: ./tareas/20261004-012404-sensor/TAREA.md
4

Listar tareas abiertas

Muestra las tareas con su ID, estado, prioridad y etiquetas, ordenadas por prioridad descendente.

tasks list 
$ tasks list
20261004-012404-sensor ABIERTA P70 [sensor] Investigar defecto en sensor
5

Inspeccionar el contexto completo

Lee el estado, metadatos y todas las notas acumuladas para retomar el trabajo sin fricción.

tasks show 
$ tasks show sensor
ID:        20261004-012404-sensor
Título:    Investigar defecto en sensor
Estado:    ABIERTA
Prioridad: 70
Etiquetas: sensor
Ruta:      ./tareas/20261004-012404-sensor/TAREA.md

(sin descripción adicional)
6

Cerrar la tarea

Actualiza el estado a CERRADA mediante reemplazo atómico, preservando el resto del archivo.

tasks close 
$ tasks close sensor
Tarea cerrada: 20261004-012404-sensor

arquitectura

Diseñado para la colaboración real

Markdown La tarea es la verdad

Sin servicios en la nube ni bases de datos desconectadas. Clonás el repositorio y tenés todas las tareas, sus notas y sus adjuntos locales listos para leer con cualquier editor de texto habitual.

Relevo Un único próximo paso

El contexto no se pierde cuando se reinicia una sesión de chat o se llena la ventana de un modelo. El colaborador lee tasks show y antes de terminar deja anotado el próximo paso exacto en TAREA.md.

Git Auditoría y trazabilidad

Los commits nombran la tarea (<ID>: …) y tasks follow audita la cobertura. Además, tasks facts emite evidencia relacional para validar contra políticas de Oracle.
