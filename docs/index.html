en marcha

Recorrido de 60 segundos

Seis comandos esenciales para inicializar, crear, documentar, listar, inspeccionar y cerrar tareas, con salidas reales.

1

Inicializar el repositorio

Crea el directorio tareas/ con su archivo explicativo README.md.

tasks init
$ tasks init
Tracker de tareas inicializado en ./tareas
2

Crear una tarea

Crea una nueva carpeta con su plantilla TAREA.md, metadatos y sufijo determinista.

tasks new
$ tasks new "Investigar defecto en sensor" --etiqueta sensor --prioridad 70 --sufijo sensor
Tarea creada: 20260927-120000-sensor
Ruta: ./tareas/20260927-120000-sensor/TAREA.md
3

Asentar una nota de avance

Agrega notas de progreso fechadas en UTC de forma atómica en el cuerpo de la tarea.

tasks note
$ tasks note sensor "Medición preliminar en banco de pruebas"
Nota agregada a la tarea 20260927-120000-sensor
Documento: ./tareas/20260927-120000-sensor/TAREA.md
4

Listar tareas abiertas

Muestra las tareas con su ID, estado, prioridad y etiquetas, ordenadas dinámicamente.

tasks list
$ tasks list
20260927-120000-sensor ABIERTA P70 [sensor] Investigar defecto en sensor
5

Inspeccionar el contexto completo

Lee el estado, metadatos y todas las notas acumuladas para retomar el trabajo sin fricción.

tasks show
$ tasks show sensor
ID:        20260927-120000-sensor
Título:    Investigar defecto en sensor
Estado:    ABIERTA
Prioridad: 70
Etiquetas: sensor
Ruta:      ./tareas/20260927-120000-sensor/TAREA.md

(sin descripción adicional)
6

Cerrar la tarea

Actualiza el estado a CERRADA mediante reemplazo atómico, preservando el resto del archivo.

tasks close
$ tasks close sensor
Tarea cerrada: 20260927-120000-sensor

arquitectura

Diseñado para la colaboración real

Markdown La tarea es la verdad

Sin servicios en la nube ni bases de datos desconectadas. Clonás el repositorio y tenés todas las tareas, sus notas y sus adjuntos locales listos para leer con cualquier editor.

Relevo Entre personas y agentes

El contexto no se pierde cuando se reinicia una sesión de chat o se llena la ventana de un modelo. El agente lee tasks show y antes de terminar deja anotado el próximo paso con tasks note.

Git Auditoría y trazabilidad

Los commits nombran la tarea (<ID>: …) y tasks follow audita la cobertura. Además, tasks facts emite evidencia estructurada para validar contra políticas de Oracle.
